Your first game

Set up a game project next to the engine, build it, and put a sprite on screen. The code is the Hello Janus example; the project files below were built and run against the documented commit.

1. Lay out the project

Create a folder for your game with the engine inside it. This is the same layout as ProtoRPG:

MyGame/
├── CMakeLists.txt
├── vcpkg.json copy of Engine/vcpkg.json
├── Engine/ the engine repository
├── Resources/ your assets (images, levels, ...)
├── Config/ project config files
└── Game/
└── src/
└── main.cpp
  • vcpkg.json must be in the top-level folder so vcpkg installs the engine's dependencies (Installing and building).
  • Game/src/ holds your game's code. Add more .cpp files there and list them in add_executable().
  • Everything in Resources/ is copied to Build/<config>/bin/Resources after each build, and the engine registers every file in it as an asset.
  • Config/ is created by the build if it is missing and copied to Build/<config>/bin/Config/Resources (cmake_modules/MoveConfigFiles.cmake:9). At the documented commit the engine does not read from that folder.
  • The engine reads its settings from Resources/Config instead. Create that folder and put a copy of Engine/Config/filesystem.json in it: the file tells the engine which file extensions are textures, shaders, and so on. The folder must exist even if it is empty, or the engine stops at startup (see Files and the working directory).

2. Write CMakeLists.txt

cmake_minimum_required(VERSION 4.2)
project(MyGame) # must match the executable name below
set(CMAKE_CXX_STANDARD 26)
# Put the engine and the game in one output folder: MyGame/Build/<config>/bin
list(APPEND CMAKE_MODULE_PATH "${CMAKE_CURRENT_SOURCE_DIR}/Engine/cmake_modules")
include(DetermineOutputDir)
add_subdirectory(Engine)
add_executable(MyGame Game/src/main.cpp)
target_link_libraries(MyGame PRIVATE Engine)
# After each build, copy MyGame/Resources (and MyGame/Config) next to the executable
include(MoveConfigFiles)

This is the same setup as ProtoRPG's root CMakeLists.txt. Two engine CMake helpers do the work:

  • DetermineOutputDir sets CMAKE_RUNTIME_OUTPUT_DIRECTORY to Build/<config>/bin under your game folder (cmake_modules/DetermineOutputDir.cmake:3). The engine uses the same folder, so its Resources/Shaders end up next to your game.
  • MoveConfigFiles adds a post-build step to the target named like the project, which is why project() and add_executable() use the same name (cmake_modules/MoveConfigFiles.cmake:9).

3. Write main.cpp

Every Janus program follows the same shape:

  1. Register anything the engine needs before it starts.
  2. Call Engine::InitializePlugins().
  3. Create entities and systems.
  4. Call Engine::Run(), which returns when the window is closed.
  5. Call Engine::TeardownPlugins().
  6. End with std::quick_exit(0) rather than returning, to avoid a known crash after shutdown (Shutdown).

Here is the complete Hello Janus example. It generates its textures in code, so it needs no image files:

Hello Janus: a camera, a light, a background and one spriteexamples/modules/HelloJanus.cpp

// Hello Janus: the smallest program that puts something on screen.
//
// It shows the four things every Janus program needs before anything is visible:
// 1. a texture for the debug-collider overlay, registered as "CollisionTexture"
// 2. a camera entity
// 3. at least one light
// 4. a sprite on the Background render layer (it clears the screen each frame)
// It uses no files: textures are generated in memory.
#include <Module.hpp>
#include <Log/Module.hpp>
#include <Filesystem/Module.hpp>
#include <Types/Graphics.hpp>
#include <Gameplay/ECS/Module.hpp>
#include <Gameplay/ECS/Modules/TransformModule.hpp>
#include <Gameplay/ECS/Modules/GraphicsModule.hpp>
#include <Rendering/Components/RenderingComponent.hpp>
#include <cstdlib>
// The engine's components (FTransformComponent, FTexture2DComponent, ...).
using namespace Components;
DECLARE_LOGGER(Hello, debug)
// Creates a square, solid-white texture in memory and registers it with the
// Filesystem module under AssetPath, as if it were an image file in Resources/.
static void RegisterSolidTexture(const std::string& AssetPath, int Size) {
SDL_Surface* surface = SDL_CreateSurface(Size, Size, SDL_PIXELFORMAT_ABGR8888);
const Uint32 white = SDL_MapSurfaceRGBA(surface, 255, 255, 255, 255);
SDL_FillSurfaceRect(surface, nullptr, white);
TObjectPtr<Graphics::STexture2D> texture;
texture->Surface = surface;
texture->Width = static_cast<float>(Size);
texture->Height = static_cast<float>(Size);
texture->AssetPath = AssetPath;
TObjectPtr<Filesystem::SAssetData> assetData;
assetData->AssetPath = AssetPath;
assetData->AssetName = AssetPath;
assetData->AssetType = Filesystem::TEXTURE;
assetData->ObjectData = texture; // already "loaded": LoadFile() returns it
Filesystem::RegisterAssetData(assetData);
}
int main() {
// The renderer loads "CollisionTexture" while the engine starts,
// so register it first.
RegisterSolidTexture("CollisionTexture", 8);
RegisterSolidTexture("White", 8);
Engine::InitializePlugins();
flecs::world& world = ECS::GetWorld();
// Camera: shows world units (0,0) to (320,180). Boundaries of 0 pin it in place.
// The light on the same entity is large enough to light the whole screen.
world.entity("Camera")
.set<FTransformComponent>({})
.set<FCameraComponent>({ .CameraSize = {320, 180}, .Boundaries = {0, 0, 0, 0} })
.set<FLightComponent>({ .Radius = 100.f, .Intensity = 2.4f });
// Background: a full-screen sprite on the Background layer.
world.entity("Background")
.set<FTransformComponent>({})
.set<FTexture2DComponent>({
.Sprite = { .SpriteSheet = {"White"} },
.TextureSize = {320, 180},
.Color = {0.10f, 0.12f, 0.18f, 1.f} })
.set<FRenderingComponent>({ .RenderLayer = Renderer::Background });
// A 32x32 orange square. Location is its top-left corner, in world units.
world.entity("Square")
.set<FTransformComponent>({ .Location = {48, 100, 0} })
.set<FTexture2DComponent>({
.Sprite = { .SpriteSheet = {"White"} },
.TextureSize = {32, 32},
.Color = {1.f, 0.55f, 0.1f, 1.f} })
.set<FRenderingComponent>({ .RenderLayer = Renderer::Entities });
Log::Hello::Info("Hello, Janus! Close the window to quit.");
Engine::Run(); // returns when the window is closed
Engine::TeardownPlugins();
// Known issue: returning from main() after TeardownPlugins() crashes in static
// destructors.
// Exit without running them (the engine has already flushed its logs).
std::quick_exit(0);
}

What each part does:

Code Why it is there
RegisterSolidTexture("CollisionTexture", 8) The renderer loads a texture called CollisionTexture during startup, for drawing debug colliders. Without it, startup fails. A file Resources/CollisionTexture.png works too.
RegisterSolidTexture("White", 8) A plain white texture. Sprites tint it with their Color, so one texture can draw any coloured rectangle.

Engine::Run() Runs the game loop: input, ECS systems, rendering. See How the engine is organized.
std::quick_exit(0) Ends the program without running static destructors, which currently crash after Engine::TeardownPlugins().

4. Build and run

cmake -S MyGame -B MyGame/build -G Ninja -DCMAKE_BUILD_TYPE=Debug ^
-DCMAKE_TOOLCHAIN_FILE=C:/vcpkg/scripts/buildsystems/vcpkg.cmake
cmake --build MyGame/build
cd MyGame\Build\Debug\bin
MyGame.exe

Run it from Build/Debug/bin: the engine finds Resources/ relative to the current working directory. In an IDE, set the run configuration's working directory to that folder.

You should see a dark blue window with an orange square, plus three Dear ImGui windows from the engine's editor tools: FPS Counter, Entity Debugger and Dear ImGui Demo. Open Entity Debugger → Entity Outliner and click Square to inspect and edit its components while the game runs.

Hello Janus: the orange square, with the engine's FPS Counter, Entity Debugger and the (collapsible) Dear ImGui demo window

5. Use your own images

Put image files under Resources/, for example MyGame/Resources/Images/Player.png. After a build it is copied next to the executable, registered at startup, and can be used by its asset path: its path under Resources/, without the extension, with Windows separators. In C++, that is "Images\\Player":

.set<Components::FTexture2DComponent>({
.Sprite = { .SpriteSheet = {"Images\\Player"} },
.TextureSize = {32, 32},
})
