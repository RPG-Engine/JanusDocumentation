How to use

Everything in a Janus game is an entity (an ID) with components (plain structs of data). Systems are functions that run every frame for every entity that has a given set of components. The engine runs them in Engine::Run().

1. Get the world. There is one flecs world, created on first use. ECS::GetWorld() returns it; use the normal flecs C++ API on it.

flecs::world& world = ECS::GetWorld();
ECS::GetWorld
flecs::world & GetWorld()
Returns the engine's flecs world.

2. Define components with DEFINE_COMPONENT, inside namespace Components. Each member is an ECS_MEMBER with a type, a name and a default value:

Three componentsexamples/ecs/Movement.cpp

namespace Components {
// World units per second.
DEFINE_COMPONENT(FVelocity,
ECS_MEMBER(glm::vec2, Value, glm::vec2(0, 0)))
// Marks the entity the keyboard controls.
DEFINE_COMPONENT(FPlayer,
ECS_MEMBER(float, Speed, 90.f))
// Marks entities that bounce off the edges of the world.
DEFINE_COMPONENT(FBounceInWorld)
}

3. Register them after Engine::InitializePlugins() with ECS_REGISTER_COMPONENT. This adds flecs reflection data (so the components can be printed, saved and edited) and a panel in the Entity Debugger:

ECS_REGISTER_COMPONENT(FVelocity, world);
ECS_REGISTER_COMPONENT
#define ECS_REGISTER_COMPONENT(ComponentName, World)

4. Create entities and give them components with set (with a value) or add (default value):

An entity with engine and game componentsexamples/ecs/Movement.cpp

// The player carries the camera and a light, so both follow it.
// Camera Boundaries are (minX, maxX, minY, maxY) for the camera's top-left corner.
const glm::vec2 worldCentre {WorldW / 2.f, WorldH / 2.f};
SpawnRect(world, worldCentre, {ActorSize, ActorSize}, {0.4f, 0.9f, 1.f, 1.f})
.set_name("Player")
.set<FPlayer>({})
.set<FVelocity>({})
.set<FCameraComponent>({
.CameraSize = {ViewW, ViewH},
.Boundaries = {0.f, WorldW - ViewW, 0.f, WorldH - ViewH},
})
.set<FLightComponent>({
.Radius = 0.6f,
.Intensity = 4.f,
.PositionOffset = {ActorSize / 2, ActorSize / 2},
});

5. Add systems. A system lists the components it needs; its function runs once per matching entity, every frame:

Three systemsexamples/ecs/Movement.cpp

// 1. Player input -> velocity. Only matches the entity with FPlayer.
world.system<const FPlayer, FVelocity>("PlayerInput")
.each([](const FPlayer& player, FVelocity& velocity) {
glm::vec2 direction = Input::GetValue(Input::Actions::Move);
if (glm::length(direction) > 1.f) {
direction = glm::normalize(direction); // no faster diagonals
}
velocity.Value = direction * player.Speed;
});
// 2. Velocity -> position, for every entity that has both components.
world.system<FTransformComponent, const FVelocity>("ApplyVelocity")
.each([](flecs::iter& it, size_t, FTransformComponent& transform,
const FVelocity& velocity) {
transform.Location.x += velocity.Value.x * it.delta_time();
transform.Location.y += velocity.Value.y * it.delta_time();
});
// 3. Keep everything inside the world.
// Bouncers reverse direction; the player just stops.
world.system<FTransformComponent,
FVelocity,
const FTexture2DComponent>("StayInWorld")
.kind(flecs::PostUpdate)
.each([](flecs::entity entity, FTransformComponent& transform,
FVelocity& velocity, const FTexture2DComponent& sprite) {
const bool bBounce = entity.has<FBounceInWorld>();
const glm::vec2 max = glm::vec2(WorldW, WorldH) - sprite.TextureSize;
for (int axis = 0; axis < 2; ++axis) {
float& location = transform.Location[axis];
if (location < 0.f || location > max[axis]) {
location = glm::clamp(location, 0.f, max[axis]);
if (bBounce) {
velocity.Value[axis] = -velocity.Value[axis];
}
}
}
});

6. Inspect it live. Open Entity Debugger → Entity Outliner in the running game to see entities with an FTransformComponent, select one, and edit its registered components.

Defining components

Macro Makes Register with
DEFINE_COMPONENT (Name, members...) The struct, reflection data and an Entity Debugger panel ECS_REGISTER_COMPONENT
DEFINE_COMPONENT_NO_DEBUG (Name, members...) The struct and reflection data, no panel ECS_REGISTER_COMPONENT_NO_DEBUG

All three variants, and plain flecs tagsexamples/ecs/ComponentsAndQueries.cpp

namespace Components {
// 1. DEFINE_COMPONENT: a struct with reflection data
// and an automatic Entity Debugger panel.
DEFINE_COMPONENT(FHealth,
ECS_MEMBER(float, Current, 100.f),
ECS_MEMBER(float, Max, 100.f))
// 2. DEFINE_COMPONENT_NO_DEBUG: reflection data, but no Entity Debugger panel.
DEFINE_COMPONENT_NO_DEBUG(FWander,
ECS_MEMBER(glm::vec2, Target, glm::vec2(0, 0)),
ECS_MEMBER(float, Speed, 30.f))
// 3. DEFINE_COMPONENT_OVERRIDE_DEBUG: you supply functions that draw before
// and after the automatic member widgets. Declare them first; the component
// type is not defined yet.
struct FUnit;
void PreDrawUnit(FUnit* Unit);
void PostDrawUnit(FUnit* Unit);
DEFINE_COMPONENT_OVERRIDE_DEBUG(FUnit, PreDrawUnit, PostDrawUnit,
ECS_MEMBER(float, Size, 8.f))
// Settings shared by every unit, stored on the engine's global entity.
DEFINE_COMPONENT(FTeamSettings,
ECS_MEMBER(float, DamagePerHit, 25.f),
ECS_MEMBER(SDL_FColor, RedColor, SDL_FColor(1.f, 0.35f, 0.35f, 1.f)),
ECS_MEMBER(SDL_FColor, BlueColor, SDL_FColor(0.35f, 0.6f, 1.f, 1.f)))
}
// Plain flecs tags: empty structs. They need no registration and carry no data.
struct RedTeam {};
struct BlueTeam {};
namespace Components {
void PreDrawUnit(FUnit* Unit) {
ImGui::TextDisabled("Custom panel drawn by PreDrawUnit");
}
void PostDrawUnit(FUnit* Unit) {
if (ImGui::Button("Grow")) {
Unit->Size += 2.f;
}
}
}
ECS_REGISTER_COMPONENT(FHealth, world);
ECS_REGISTER_COMPONENT_NO_DEBUG(FWander, world);
ECS_REGISTER_COMPONENT(FUnit, world);
ECS_REGISTER_COMPONENT(FTeamSettings, world);

Rules:

  • Use the macros inside namespace Components; the registration macros refer to Components::Name.
  • A component with no members (DEFINE_COMPONENT(FPlayer)) works as a marker. Plain empty structs also work as flecs tags, without registration, but don't appear in the Entity Debugger.
  • The Entity Debugger draws members of type float, glm::vec2/3/4, SDL_FColor, Filesystem::SSoftAssetPath and Renderer::EInstanceLayer (include/Gameplay/ECS/Components.hpp:125). Members of other types (int, bool, ...) are stored and reflected but not shown. To draw another type, specialize Components::ECSDebug_DrawElement<T> the way include/Rendering/SpriteInstanceContainer.hpp:28 does for render layers.
  • Member types must be known to flecs reflection: built-in types, or one of the types listed above.

Systems, phases and queries

flecs runs systems in phases, in order: OnLoad, PostLoad, PreUpdate, OnUpdate (the default), OnValidate, PostUpdate, PreStore, OnStore. Choose one with .kind(...). The engine adds:

Phase Runs after Used for
ECS::Phase::OnInput() PostUpdate Defined by the Input module (include/Input/Module.hpp:9); ProtoRPG moves its player here
ECS::Phase::OnCollision PostUpdate Defined at startup for collision checks (src/Gameplay/ECS/Module.cpp:58)
ECS::Phase::OnPreRender() OnStore The renderer gathers sprites, lights and the camera here (include/Rendering/Module.hpp:18)

Add your own with DEFINE_NEW_ECS_PHASE:

A custom phase and systems that use itexamples/ecs/ComponentsAndQueries.cpp

// A new pipeline phase that runs after flecs::PostUpdate.
// Use it with .kind(ECS::Phase::OnLateGameplay()).
DEFINE_NEW_ECS_PHASE(OnLateGameplay, PostUpdate)
// Input: act on the queries.
world.system<const FTeamSettings>("TeamInput")
.each([](const FTeamSettings& settings) {
if (Input::IsActionTriggered(Input::Actions::ToBlue)) {
SwitchOneUnit<RedTeam, BlueTeam>(RedUnits);
}
if (Input::IsActionTriggered(Input::Actions::ToRed)) {
SwitchOneUnit<BlueTeam, RedTeam>(BlueUnits);
}
if (Input::IsActionTriggered(Input::Actions::HurtBlue)) {
BlueHealth.each([&settings](FHealth& health) {
health.Current -= settings.DamagePerHit;
});
}
});
// Wander towards a target; pick a new one on arrival.
// FUnit::Size drives the sprite size.
world.system<FTransformComponent,
FWander,
FTexture2DComponent,
const FUnit>("Wander")
.each([](flecs::iter& it, size_t, FTransformComponent& transform,
FWander& wander, FTexture2DComponent& sprite, const FUnit& unit) {
const glm::vec2 position {transform.Location.x, transform.Location.y};
const glm::vec2 toTarget = wander.Target - position;
if (glm::length(toTarget) < 2.f) {
wander.Target = RandomPoint();
return;
}
const float distance = wander.Speed * it.delta_time();
const glm::vec2 step = glm::normalize(toTarget) * distance;
transform.Location.x += step.x;
transform.Location.y += step.y;
sprite.TextureSize = {unit.Size, unit.Size};
});
// Runs in the custom phase, after all gameplay:
// remove units that ran out of health.
world.system<const FHealth>("RemoveDead")
.kind(ECS::Phase::OnLateGameplay())
.each([](flecs::entity entity, const FHealth& health) {
if (health.Current <= 0.f) {
entity.destruct();
}
});

Queries find entities outside a system's own match, for collision checks or counting. Build them once and keep them:

Queries filtered by tagsexamples/ecs/ComponentsAndQueries.cpp

// Queries are created once and reused. These two filter on the team tags.
static flecs::query<const FUnit> RedUnits;
static flecs::query<const FUnit> BlueUnits;
static flecs::query<FHealth> BlueHealth;
RedUnits = world.query_builder<const FUnit>().with<RedTeam>().build();
BlueUnits = world.query_builder<const FUnit>().with<BlueTeam>().build();
BlueHealth = world.query_builder<FHealth>().with<BlueTeam>().build();

Observers run as soon as something happens to an entity (a component added, set or removed) instead of every frame:

Observersexamples/ecs/ComponentsAndQueries.cpp

// Observers run immediately when something happens to an entity,
// instead of every frame.
world.observer<FTexture2DComponent>("PaintRed")
.with<RedTeam>()
.event(flecs::OnAdd)
.each([](FTexture2DComponent& sprite) {
sprite.Color = ECS::GetGlobalSystemsEntity().get<FTeamSettings>().RedColor;
});
world.observer<FTexture2DComponent>("PaintBlue")
.with<BlueTeam>()
.event(flecs::OnAdd)
.each([](FTexture2DComponent& sprite) {
sprite.Color = ECS::GetGlobalSystemsEntity().get<FTeamSettings>().BlueColor;
});
// OnRemove also fires when an entity is destroyed.
// The component can still be read here.
world.observer<const FHealth>("UnitDefeated")
.event(flecs::OnRemove)
.each([](flecs::entity unit, const FHealth& health) {
if (health.Current <= 0.f) {
Log::Teams::Info("{} was defeated", unit.name().c_str());
}
});

Prefabs hold components that many entities start with:

A prefab and its instancesexamples/ecs/Spawning.cpp

// A prefab holds the components every spark starts with. Instances created with
// is_a(prefab) get their own copy of each one, so they can be changed per spark.
flecs::entity sparkPrefab = world.prefab("Spark")
.set<FTexture2DComponent>({
.Sprite = { .SpriteSheet = {"White"} },
.TextureSize = {3.f, 3.f},
.Color = {1.f, 0.8f, 0.3f, 1.f},
})
.set<FRenderingComponent>({ .RenderLayer = Renderer::Entities })
.set<FLifetime>({});
// Creates one spark at Origin, flying in a random direction.
auto spawnSpark = [sparkPrefab](const flecs::world& World, glm::vec2 Origin) {
const float angle = RandomRange(0.f, 6.2831853f);
const float speed = RandomRange(20.f, 90.f);
const float life = RandomRange(0.6f, 1.8f);
const glm::vec2 velocity {std::cos(angle) * speed, std::sin(angle) * speed};
World.entity()
.is_a(sparkPrefab)
.set<FTransformComponent>({ .Location = {Origin.x, Origin.y, 0.f} })
.set<FVelocity>({ .Value = velocity })
.set<FLifetime>({ .Remaining = life, .Total = life });
};

The flecs manual covers all of these in depth: systems, queries, observers, prefabs.

The global entity and selection

  • ECS::GetGlobalSystemsEntity() returns one entity created on first use. Store game-wide settings on it as components; the Entity Debugger shows them under Global Entity. The mouse-hover system keeps its Components::FMouseState there.
  • ECS::SelectEntity() chooses which entity the Entity Debugger shows; ECS::GetSelectedEntity() returns it.

Settings on the global entityexamples/ecs/ComponentsAndQueries.cpp

// The global entity is listed under "Global Entity" in the Entity Debugger,
// so these settings can be edited live.
flecs::entity settingsEntity = ECS::GetGlobalSystemsEntity();
settingsEntity.set<FTeamSettings>({});

Things to watch out for

  • Changes made inside a system (creating, destroying, set, add, remove) are deferred until the system finishes. Reading a component you just set on another entity in the same system returns the old value, and an entity created in the system has no components yet (use try_get).
  • Outside systems (for example in an editor tool's ImGui code), changes are immediate. Wrap loops that destroy entities in world.defer(...).
  • ECS::Module() gives flecs 8 worker threads (src/Gameplay/ECS/Module.cpp:34), but systems only use them if you add .multi_threaded(). Engine and example systems are single-threaded.
  • The Entity Outliner only lists entities that have an FTransformComponent.
  • The Entity Debugger's Save Entity button writes a flecs script to Resources/Output/ECS/<name>, which must already exist. Load such a file with world.script_run(name, text).
  • ECS::TeardownModule() destroys the world, which then is destroyed again at exit; see Shutdown.
