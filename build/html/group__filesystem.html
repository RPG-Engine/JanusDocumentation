Filesystem

Finds every file under Resources/, gives each one an asset path, and loads files into typed asset objects on demand. More...

How to use

  1. Put files under Resources/ in your game folder. After a build they are copied next to the executable, and at startup every file is registered.
  2. Refer to a file by its asset path: its path under Resources/, without the extension, with the platform's separators. Resources/Images/Player.png is Images\Player, written "Images\\Player" in C++.
  3. Look it up with Filesystem::GetAssetData() to get its Filesystem::SAssetData: the real file path, name, extension and type.
  4. Load it with Filesystem::Importers::LoadFile<T>(path). T is the asset type you want: STextFileAsset, SRawFileAsset, Graphics::STexture2D, or your own. The result is cached, so loading again is cheap.
  5. Store references in components as a Filesystem::SSoftAssetPath (just the path string), not as loaded objects.

Listing assets and reading oneexamples/modules/AssetsAndMemory.cpp

// Every file under Resources/ has an asset path:
// its path relative to Resources/, without the extension.
const std::vector<std::string> allPaths = Filesystem::GetAllAssetPaths();
Log::Assets::Info("{} assets registered", allPaths.size());
// Asset types come from Resources/Config/filesystem.json (file extension -> type).
for (const auto& shader : Filesystem::GetAllAssetPaths(Filesystem::SHADER)) {
Log::Assets::Info("Shader asset: {}", shader.AssetPath);
}
// GetAssetData accepts '/' or '\' separators.
// It logs an error and returns null if nothing matches.
const TObjectPtr<Filesystem::SAssetData> data =
Filesystem::GetAssetData("Shaders/Compiled/PullSpriteBatch.vert");
if (data.IsValid()) {
Log::Assets::Info("Name: {} Extension: {} File: {}",
data->AssetName, data->AssetExtension,
data->AssetFilePathRaw.string());
}

Loading a text fileexamples/modules/AssetsAndMemory.cpp

// LoadFile<T> reads the file once and caches the result on the asset's SAssetData.
// The file is Resources/Shaders/FragmentShaderSrc.frag.hlsl
const std::string shaderPath = "Shaders/FragmentShaderSrc.frag";
if (Filesystem::Importers::AssetExists<STextFileAsset>(shaderPath)) {
TObjectPtr<STextFileAsset> source =
Filesystem::Importers::LoadFile<STextFileAsset>(shaderPath);
std::istringstream lines(source->Data);
std::string firstLine;
std::getline(lines, firstLine);
Log::Assets::Info("{} is {} characters long. First line: {}",
source->GetName(), source->Data.size(), firstLine);
// Loading again returns the same object from the cache.
TObjectPtr<STextFileAsset> again =
Filesystem::Importers::LoadFile<STextFileAsset>(shaderPath);
Log::Assets::Info("Cached: {}", again == source);
}

The asset path is computed by Filesystem::FilePathToAssetPath() (src/Filesystem/FilesystemTypes.cpp:49): the path relative to Resources/, with the last extension removed.

  • Filesystem::GetAssetData() converts / to \\endiskip before looking up (src/Filesystem/Module.cpp:67), so "Images/Player" works there.
  • Filesystem::IsValid() does not convert (src/Filesystem/Module.cpp:119), and the renderer uses it to decide whether to draw a sprite. Always use \\ in paths you store in components. For paths built at runtime, std::filesystem::path(p).make_preferred().string() gives the right form.
  • Two files that differ only in their extension get the same asset path. Only the first one found is registered. That is why the three compiled forms of each shader (.dxil, .msl, .spv) share one asset: the renderer picks the right file itself.

Asset types

Resources/Config/filesystem.json maps file extensions to Filesystem::EAssetType values. Each file's type is set when it is registered (src/Filesystem/FilesystemTypes.cpp:24):

Engine exampleThe engine's extension tableConfig/filesystem.json:1

{
"AssetTypes" : {
"TEXTURE": [".png", ".jpg"],
"SHADER": [".dxil", ".spv", ".msl"],
"FONT": [".ttf", ".otf"],
"PREFAB": [".prefab"],
"LEVEL": [".level"]
}
}

The type is only a label. LoadFile<T> decides how to read a file from T, not from the asset type. The type is used by Filesystem::GetAllAssetPaths(EAssetType) and by editor drop-downs that list, for example, only textures.

Note
The engine copies its own Config/ folder to <output>/Config/Resources, not to <output>/Resources/Config (cmake_modules/MoveConfigFiles.cmake:9). Copy filesystem.json into your game's Resources/Config/ yourself, as described in Your first game.

Loading and caching

LoadFile<T>(path) finds the asset's Filesystem::SAssetData and returns SAssetData::ObjectData if it is already loaded. Otherwise it calls the loader for T, stores the result in ObjectData, sets the asset's AssetPath and name, and returns it (include/Filesystem/Importers/Importer.hpp:63).

Warning
An asset is cached once, for the first type it is loaded as. Loading the same path again as a different type returns the cached object cast to the new type, which is wrong. Load each file as one type only.

Your own asset types

Derive from SAsset, then specialize Filesystem::Importers::LoadAsset for your type. DEFINE_ASSET_LOADER declares the specialization:

A custom asset type and its loaderexamples/modules/AssetsAndMemory.cpp

// A custom asset type: derive from SAsset, then give LoadAsset<T> a specialization
// that builds one from the file. DEFINE_ASSET_LOADER declares the specialization
// (put it in a header if other files use it).
struct SLineCountAsset : SAsset {
size_t Lines = 0;
};
DEFINE_ASSET_LOADER(SLineCountAsset, )
namespace Filesystem::Importers {
template<>
TObjectPtr<SLineCountAsset> LoadAsset<SLineCountAsset>(
const TObjectPtr<SAssetData>& InAssetData) {
std::ifstream file {InAssetData->AssetFilePathRaw};
const std::istreambuf_iterator<char> begin(file), end;
TObjectPtr<SLineCountAsset> asset;
asset->Lines = std::count(begin, end, '\n');
return asset;
}
}
// LoadFile works the same for your own types. Note that an asset is cached for
// the first type it is loaded as, so don't load one file as two different types.
const std::string vertexPath = "Shaders/VertexShaderSrc.vert";
TObjectPtr<SLineCountAsset> vertexSource =
Filesystem::Importers::LoadFile<SLineCountAsset>(vertexPath);
Log::Assets::Info("{} has {} lines", vertexSource->GetName(), vertexSource->Lines);

Assets made in code

Register a Filesystem::SAssetData whose ObjectData is already set. LoadFile then returns that object without touching the disk, and the renderer can draw it like any image. This is how every example creates its textures:

Registering a texture generated at runtimeexamples/modules/AssetsAndMemory.cpp

// Builds a texture in code and registers it like a file.
// SDL_PIXELFORMAT_ABGR8888 is the byte order (R, G, B, A) the renderer uploads,
// the same format image files are converted to.
static void RegisterCheckerTexture(const std::string& AssetPath, int Size,
int Squares) {
SDL_Surface* surface = SDL_CreateSurface(Size, Size, SDL_PIXELFORMAT_ABGR8888);
const Uint32 light = SDL_MapSurfaceRGBA(surface, 235, 235, 240, 255);
const Uint32 dark = SDL_MapSurfaceRGBA(surface, 70, 80, 110, 255);
const int cell = Size / Squares;
for (int y = 0; y < Squares; ++y) {
for (int x = 0; x < Squares; ++x) {
const bool bLight = (x + y) % 2 == 0;
const SDL_Rect rect {x * cell, y * cell, cell, cell};
SDL_FillSurfaceRect(surface, &rect, bLight ? light : dark);
}
}
TObjectPtr<Graphics::STexture2D> texture; // TObjectPtr<T>() creates a new T
texture->Surface = surface;
texture->Width = static_cast<float>(Size);
texture->Height = static_cast<float>(Size);
texture->AssetPath = AssetPath;
TObjectPtr<Filesystem::SAssetData> assetData;
assetData->AssetPath = AssetPath; // the key GetAssetData() looks up
assetData->AssetName = AssetPath;
assetData->AssetType = Filesystem::TEXTURE;
assetData->ObjectData = texture; // already loaded: LoadFile() returns it
Filesystem::RegisterAssetData(assetData);
}
// Assets can be registered at any time.
// The renderer uploads a texture the first time it is drawn.
// Asset paths use the platform's preferred separator ('\' on Windows), like
// the paths of scanned files. GetAssetData() converts '/' for you, but
// Filesystem::IsValid() (used by the renderer) does not.
std::filesystem::path checkerFile = "Generated/Checker";
const std::string checkerPath = checkerFile.make_preferred().string();
RegisterCheckerTexture(checkerPath, 64, 8);
const bool bValid = Filesystem::IsValid(Filesystem::SSoftAssetPath(checkerPath));
Log::Assets::Info("{} valid: {}", checkerPath, bValid);

Assets can be registered before Engine::InitializePlugins() (needed for CollisionTexture) or at any time after. A file found by the startup scan with the same asset path is skipped.

Filesystem::SConfig is a small helper for JSON settings files under Resources/Config/. A config type derives from SConfig<Self>, says where its file is, and lists its fields for nlohmann/json. The engine's own Filesystem::SFilesystemConfig reads filesystem.json:

Things to watch out for

  • Resources/Config must exist in the working directory, or Filesystem::InitializeAllResources() throws (src/Filesystem/Module.cpp:27).
  • At startup the log shows Could not find asset [Config\Filesystem] once, even when the file is there: the file's own type is looked up before it is registered. It is harmless.
  • LoadFile(path) throws AssetCouldNotLoadException when the path is unknown. TryLoadFile(path) throws nullptr instead; it does not return an empty pointer. Check with AssetExists<T>(path) or Filesystem::IsValid() first.
  • Filesystem::Module() is declared but not defined. Don't call it; the engine calls Filesystem::InitializeAllResources().
  • More in Filesystem.
