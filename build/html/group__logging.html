Log

Named, per-module loggers built on spdlog. More...

Overview

Each module declares its own logger once, then logs with std::format-style messages to the console and to log files.

How to use

This is all most code needs. Declare a logger once, at the top of a source file, and log through its namespace. Game code works the same way as engine code.

1. Declare the logger with a name and a minimum level. The level is one of err, warn, info, debug or trace:

What it does

Every engine module gets its own named logger. Messages are tagged with that name, so the output shows where each line came from. For example, the line written by src/Filesystem/Module.cpp:28 looks like this (an illustration of the format set at src/Log/Module.cpp:30; your date, time and path will differ):

[11/22/26 15:10:02] [LogFilesystem] info: Loading config files in .../Config...

The Log module:

  1. Creates loggers when a module declares one with DECLARE_LOGGER. Each logger is a Log::SLogger that registers itself with spdlog when it is constructed.
  2. Routes output to the console, to a log file under <exe dir>/Logs/, or both. Loggers that write to the same file share one file sink.
  3. Filters by level: each logger drops messages below its configured level (trace < debug < info < warn < err).
  4. Flushes every 3 seconds, and on shutdown copies each log file to a timestamped name (e.g. JanusEngine-2026-11-22-h15m10.log, with the time in UTC).

Things to watch out for

  • Declare loggers in source files, not headers. DECLARE_LOGGER defines static functions and a static logger. In a header, every file that includes it gets its own copy, and other modules can use what was meant to be a private logger.
  • A logger's name is registered once. If two files declare the same name (Filesystem does, in src/Filesystem/Module.cpp:10 and src/Filesystem/FilesystemTypes.cpp:12), the second one reuses the spdlog logger the first one created (src/Log/Module.cpp:81). Its own output settings are ignored, but its level filter still applies.
  • A default Log::SLoggerConfiguration has no outputs. Its LogOptions is LOG_NONE, so a logger built from it discards every message. Set LogOptions explicitly when you build a configuration yourself.
  • Verbose (trace) messages don't appear by default. Log::Module() calls spdlog::set_level(debug) (src/Log/Module.cpp:53), which spdlog applies to every registered logger. Trace-level messages are dropped even for a logger declared with trace.
  • Loggers are created during static initialization. Log::RegisterLogger() reads the default pattern and log folder from static std::string variables in src/Log/Module.cpp:27. C++ does not define the order in which statics in different source files are initialized, so a logger declared in another file may be constructed before those strings are set.
