Renderer

Draws sprites in five layers on the GPU, follows a camera entity and lights the image with 2D lights. More...

Overview

Sprites are entities with three components.

Sourceinclude/Rendering/ · src/Rendering/ · Resources/Shaders/
Include#include <Rendering/Components/RenderingComponent.hpp> (sprite components; includes <Rendering/Module.hpp>) · #include <Rendering/RenderingBackend.hpp> (layers, low-level calls)
NamespaceRenderer; components in Components
Started byEngine::InitializePlugins() calls Renderer::Module(), which opens the window
Built onSDL3 GPU API with the Vulkan backend, SDL_shadercross for shaders
ExamplesRendering · Hello Janus · every game

How to use

  1. Set up the scene once (see The minimum for a visible game): a CollisionTexture asset before startup, a camera entity, at least one light, and a sprite on the Background layer.
  2. Make a sprite: give an entity an Components::FTransformComponent (where), an Components::FTexture2DComponent (which texture, how big, what colour) and an Components::FRenderingComponent (which layer).
  3. Move it by changing FTransformComponent::Location in a system. The renderer picks up the new position every frame.

Camera, light, background and a spriteexamples/modules/HelloJanus.cpp

// The renderer loads "CollisionTexture" while the engine starts,
// so register it first.
RegisterSolidTexture("CollisionTexture", 8);
RegisterSolidTexture("White", 8);
Engine::InitializePlugins();
flecs::world& world = ECS::GetWorld();
// Camera: shows world units (0,0) to (320,180). Boundaries of 0 pin it in place.
// The light on the same entity is large enough to light the whole screen.
world.entity("Camera")
.set<FTransformComponent>({})
.set<FCameraComponent>({ .CameraSize = {320, 180}, .Boundaries = {0, 0, 0, 0} })
.set<FLightComponent>({ .Radius = 100.f, .Intensity = 2.4f });
// Background: a full-screen sprite on the Background layer.
world.entity("Background")
.set<FTransformComponent>({})
.set<FTexture2DComponent>({
.Sprite = { .SpriteSheet = {"White"} },
.TextureSize = {320, 180},
.Color = {0.10f, 0.12f, 0.18f, 1.f} })
.set<FRenderingComponent>({ .RenderLayer = Renderer::Background });
// A 32x32 orange square. Location is its top-left corner, in world units.
world.entity("Square")
.set<FTransformComponent>({ .Location = {48, 100, 0} })
.set<FTexture2DComponent>({
.Sprite = { .SpriteSheet = {"White"} },
.TextureSize = {32, 32},
.Color = {1.f, 0.55f, 0.1f, 1.f} })
.set<FRenderingComponent>({ .RenderLayer = Renderer::Entities });
Log::Hello::Info("Hello, Janus! Close the window to quit.");
Engine::Run(); // returns when the window is closed
Engine::TeardownPlugins();
// Known issue: returning from main() after TeardownPlugins() crashes in static
// destructors.
// Exit without running them (the engine has already flushed its logs).
std::quick_exit(0);

The renderer's own systems run in the ECS::Phase::OnPreRender() phase, after all game systems (src/Rendering/Vulkan_Renderer.cpp:425):

System Reads Does
Render transforms Transform, Texture2D, Rendering Writes each sprite into its layer's batch for its texture
Render Camera Transform, Camera Builds the view and projection
Render Lighting Transform, Light Collects the lights for this frame

Sprites

Components::FTexture2DComponent says what to draw:

Member Meaning
Sprite.SpriteSheet The texture's asset path, e.g. "Images\\Player" (Windows separators; see Asset paths).
Sprite.UVCoords, Sprite.WHCoords The part of the texture to draw: top-left corner and size, as fractions of the texture (0 to 1). Default: the whole texture.
TextureSize The sprite's size in world units (default 32 × 32).
Color Multiplied with the texture. White leaves it unchanged; alpha below 1 is see-through.
BoundingBox Not used when drawing (only by the legacy Renderer::RegisterEntity()).

To draw one cell of a sprite sheet, set UVCoords and WHCoords. A 64 × 64 texture with four 32 × 32 cells has cells at (0,0), (0.5,0), (0,0.5) and (0.5,0.5), each (0.5,0.5) in size:

Drawing sprite-sheet cellsexamples/modules/Rendering.cpp

// UVCoords is the top-left of the cell and WHCoords its size,
// both as fractions of the texture (0..1).
for (int cell = 0; cell < 4; ++cell) {
const glm::vec2 uv {(cell % 2) * 0.5f, (cell / 2) * 0.5f};
world.entity()
.set<FTransformComponent>({ .Location = {16.f + cell * 36.f, 16.f, 0.f} })
.set<FTexture2DComponent>({
.Sprite = {
.SpriteSheet = {"Atlas"},
.UVCoords = uv,
.WHCoords = {0.5f, 0.5f},
},
.TextureSize = {32.f, 32.f},
})
.set<FRenderingComponent>({ .RenderLayer = Renderer::Entities });
}

Tint, transparency and rotation:

Colour, alpha and rotationexamples/modules/Rendering.cpp

// Color multiplies the texture. Alpha below 1 is see-through.
for (int i = 0; i < 5; ++i) {
const SDL_FColor orange {1.f, 0.75f, 0.3f, 0.2f + i * 0.2f};
SpawnSprite(world, "White", {16.f + i * 22.f, 120.f}, {18.f, 18.f}, orange);
}
const SDL_FColor noTint {1.f, 1.f, 1.f, 1.f};
flecs::entity spinner =
SpawnSprite(world, "Atlas", {150.f, 112.f}, {32.f, 32.f}, noTint)
.set_name("Spinner");
// Show only the red square cell
spinner.get_mut<FTexture2DComponent>().Sprite.WHCoords = {0.5f, 0.5f};
world.system<FTransformComponent>("Spin")
.each([spinner](flecs::entity entity, FTransformComponent& transform) {
if (entity == spinner) {
// Radians per second
transform.Rotation.x += entity.world().delta_time();
}
});

Textures are uploaded to the GPU the first time a sprite uses them; that sprite appears one frame later (src/Rendering/Vulkan_Renderer.cpp:589). Upload earlier with Renderer::LoadTextureToVRam() if that matters.

Layers and draw order

Components::FRenderingComponent chooses the layer (Renderer::EInstanceLayer). Layers are drawn in this order, each on top of the previous:

Layer Use for Each frame
Background The backdrop; level tiles from Renderer::LoadLevel() Drawing it clears the screen. Every texture group on this layer clears again, so use one texture here.
Entities (default) Everything that moves, appears or disappears Emptied and rebuilt (src/Rendering/Vulkan_Renderer.cpp:783)
Foreground Static things in front of entities Kept. Destroyed entities stay visible.
Debug Static debug markers Kept
Overlay Static things on top of everything Kept

One square per layerexamples/modules/Rendering.cpp

// Layers are drawn in order: Background, Entities, Foreground, Debug, Overlay.
// Each square overlaps the previous one and is drawn on top of it.
const glm::vec2 square {36.f, 36.f};
const SDL_FColor red {0.9f, 0.35f, 0.35f, 1.f};
const SDL_FColor green {0.35f, 0.85f, 0.45f, 1.f};
const SDL_FColor blue {0.35f, 0.55f, 0.95f, 1.f};
const SDL_FColor white {1.f, 1.f, 1.f, 0.6f};
SpawnSprite(world, "White", {200.f, 14.f}, square, red, Renderer::Entities);
SpawnSprite(world, "White", {216.f, 24.f}, square, green, Renderer::Foreground);
SpawnSprite(world, "White", {232.f, 34.f}, square, blue, Renderer::Debug);
SpawnSprite(world, "White", {248.f, 44.f}, square, white, Renderer::Overlay);

Inside a layer, sprites are batched by texture. Batches are drawn in the order each texture was first used on that layer, and inside a batch sprites are sorted by Location.y, so lower sprites are drawn over higher ones (src/Rendering/Vulkan_Renderer.cpp:553). Sprites with different textures on one layer are therefore not sorted against each other.

Y-sortingexamples/modules/Rendering.cpp

// Within a layer, sprites lower on the screen (larger Y) are drawn on top.
// The bobbing square passes in front of and behind the fixed one.
const SDL_FColor grey {0.5f, 0.5f, 0.55f, 1.f};
const SDL_FColor pink {0.95f, 0.6f, 0.9f, 1.f};
SpawnSprite(world, "White", {220.f, 120.f}, {30.f, 30.f}, grey)
.set_name("Fixed");
flecs::entity bobber =
SpawnSprite(world, "White", {232.f, 110.f}, {24.f, 24.f}, pink)
.set_name("Bobber");
world.system<FTransformComponent>("Bob")
.each([bobber](flecs::entity entity, FTransformComponent& transform) {
if (entity == bobber) {
const float seconds = static_cast<float>(SDL_GetTicks()) / 1000.f;
transform.Location.y = 115.f + std::sin(seconds / 0.6f) * 22.f;
}
});

Camera

The entity with Components::FTransformComponent and Components::FCameraComponent is the camera (src/Rendering/Vulkan_Renderer.cpp:293). With several, the last one processed wins.

Member Meaning
CameraSize How many world units the view shows, e.g. {320, 180}. Keep the 16:9 shape of the 1920 × 1080 window.
CenterSize The size of the followed entity. The camera keeps the entity's top-left corner at CameraSize / 2 - CenterSize / 2 from the view's corner, which centres an entity of that size.
Boundaries Limits for the view's top-left corner: (minX, maxX, minY, maxY). {0, 0, 0, 0} fixes the camera at the origin. For a world W × H wide, use {0, W - CameraSize.x, 0, H - CameraSize.y} to stop at the edges.

Put the camera component on the player to follow it:

A camera that follows the player and stops at the world's edgesexamples/ecs/Movement.cpp

// The player carries the camera and a light, so both follow it.
// Camera Boundaries are (minX, maxX, minY, maxY) for the camera's top-left corner.
const glm::vec2 worldCentre {WorldW / 2.f, WorldH / 2.f};
SpawnRect(world, worldCentre, {ActorSize, ActorSize}, {0.4f, 0.9f, 1.f, 1.f})
.set_name("Player")
.set<FPlayer>({})
.set<FVelocity>({})
.set<FCameraComponent>({
.CameraSize = {ViewW, ViewH},
.Boundaries = {0.f, WorldW - ViewW, 0.f, WorldH - ViewH},
})
.set<FLightComponent>({
.Radius = 0.6f,
.Intensity = 4.f,
.PositionOffset = {ActorSize / 2, ActorSize / 2},
});

Lights

After all layers are drawn, the image is lit: each pixel is its colour × 0.3 (a fixed ambient level, src/Rendering/Vulkan_Renderer.cpp:680), plus the contribution of every light. With no light at all, the lit image is never drawn and the screen stays black (src/Rendering/Vulkan_Renderer.cpp:625).

Member of Components::FLightComponent Meaning
Radius Reach of the light in screen space, not world units: about the fraction of the screen it covers. 0.35 lights roughly a third of the screen; 100 lights everything.
Intensity Brightness. A light covering everything with Intensity = 2.4 brings the image to about full brightness.
RGB Light colour (SDL_FColor, alpha unused).
PositionOffset Offset from the entity's Location, in world units.
Falloff Not used by the shader at this commit.

A fill light and two coloured lightsexamples/modules/Rendering.cpp

// A fixed camera. Without at least one light the screen stays black.
world.entity("Camera")
.set<FTransformComponent>({})
.set<FCameraComponent>({
.CameraSize = {ScreenW, ScreenH},
.Boundaries = {0, 0, 0, 0},
});
// A soft light over the whole screen,
// plus two small coloured lights that orbit the middle.
world.entity("Fill light")
.set<FTransformComponent>({})
.set<FLightComponent>({ .Radius = 100.f, .Intensity = 1.2f });
world.entity("Red light")
.set<FTransformComponent>({})
.set<FLightComponent>({
.Radius = 0.35f,
.Intensity = 4.f,
.RGB = {1.f, 0.3f, 0.2f, 1.f},
})
.set<FOrbit>({ .Center = {160.f, 90.f}, .Radius = 70.f, .Speed = 0.8f });
world.entity("Blue light")
.set<FTransformComponent>({})
.set<FLightComponent>({
.Radius = 0.35f,
.Intensity = 4.f,
.RGB = {0.2f, 0.5f, 1.f, 1.f},
})
.set<FOrbit>({
.Center = {160.f, 90.f},
.Radius = 70.f,
.Speed = 0.8f,
.Angle = 3.14159f, // start on the opposite side
});

The lighting shader is Resources/Shaders/Compiled/LightShader.frag.hlsl.

Debug colliders

While CoreTypes::bShouldDisplayDebugColliders is true, the renderer draws Renderer::CollisionInstances on top of the lit image, using the CollisionTexture asset (src/Rendering/Vulkan_Renderer.cpp:748). Fill that container yourself, one entry per collider, keyed by an ID:

Drawing collider outlinesexamples/ecs/CollisionAndHover.cpp

// Fill the renderer's debug-collider container. It is drawn on top of everything
// while CoreTypes::bShouldDisplayDebugColliders is true (toggled here by the
// ToggleDebugColliders action).
world.system<const FTransformComponent, const FColliderComponent>("DebugColliders")
.kind(ECS::Phase::OnPreRender())
.each([](flecs::entity entity, const FTransformComponent& transform,
const FColliderComponent& collider) {
const SDL_FRect rect = ColliderRect(transform, collider);
const uint32_t id = static_cast<uint32_t>(entity.id());
auto& container = Renderer::CollisionInstances;
container.AddEntity(id);
Renderer::SpriteInstance& instance = container.Instances[id];
instance.x = rect.x;
instance.y = rect.y;
instance.w = rect.w;
instance.h = rect.h;
instance.tex_w = 1.f;
instance.tex_h = 1.f;
instance.r = instance.g = instance.b = instance.a = 1.f;
});

Entries stay until you remove them with Renderer::CollisionInstances.RemoveEntity(id). Renderer::AddDebugCollision() does the same as the snippet but is deprecated and reads its rectangle as (x, y, height, width).

Levels from LDtk

World::GenerateLevel() (CoreTypes) loads a level from an LDtk project. Renderer::LoadLevel() then puts its tiles on the Background layer and returns a rectangle for every IntGrid cell with value 1, to use as collision (src/Rendering/Module.cpp:74). Layers whose name contains Grass or Ground_Base are drawn below the others.

Screen and world positions

Renderer::ScreenPosToWorldPos() converts a window position (for example from SDL_GetMouseState) to world units. It assumes a 1920 × 1080 window (src/Rendering/Vulkan_Renderer.cpp:795).

Things to watch out for

  • The window and the render target are fixed at 1920 × 1080 (src/Rendering/Vulkan_Renderer.cpp:58). Resizing stretches the image.
  • If the first sprite in a batch has an invalid texture path, the whole batch is skipped that frame (src/Rendering/Vulkan_Renderer.cpp:233).
  • At most 50 000 sprites fit in a batch (src/Rendering/Vulkan_Renderer.cpp:37).
  • flecs prints computed size (64) for 'SSprite' is larger than actual type (48) at shutdown: the reflection data registered for Graphics::SSprite doesn't match the struct (src/Rendering/Module.cpp:55). Drawing is not affected, but editing or saving a sprite's fields in the Entity Debugger may be wrong.
  • More in Rendering.
