Known issues

Engine behaviour at commit 824ee20 that may surprise you, found while writing and running the examples. Each entry links to the code and says how to work around it.

These are descriptions of the engine as it is, not of how it should be. When one is fixed, remove it here (see Documentation version).

Building and starting

Issue Workaround
The pinned commit does not compile. Engine::InitializePlugins and TeardownPlugins are declared with ENGINE_ENGINE_EXPORT, which is not defined (include/Module.hpp:17). Change both to ENGINE_EXPORT.
If SDL_Init fails, InitializePlugins() executes throw; with no active exception, which terminates the program without a message box (src/Module.cpp:76). Check the log for the SDL error.
The post-build step copies TracyClient.dll from the x64-windows triplet folder (CMakeLists.txt:75). Use the x64-windows triplet.

Shutdown

Returning from main() after Engine::TeardownPlugins() crashes with an access violation (exit code 0xC0000005). The crash happens in static destructors, after all logs are written: ECS::TeardownModule() destroys the flecs world with ecs_fini (src/Gameplay/ECS/Module.cpp:61), and the same world, a function-local static (src/Gameplay/ECS/Module.cpp:66), is destroyed again when the program exits.

Workaround: end main() with std::quick_exit(0), as every example does. Ending with std::_Exit(0) gives exit code 0 as well.

Filesystem

Issue Workaround
Resources/Config must exist in the working directory; otherwise startup throws std::filesystem::filesystem_error (src/Filesystem/Module.cpp:27). Create it, and put filesystem.json in it.
The engine's CMake copies Config/ to <output>/Config/Resources instead of <output>/Resources/Config (cmake_modules/MoveConfigFiles.cmake:9), so filesystem.json is not found and every asset type is UNDEFINED. Put a copy of filesystem.json in your game's Resources/Config/ (Your first game).
Could not find asset [Config\Filesystem] is logged once at startup even when the file exists. Harmless.
Filesystem::IsValid() compares paths exactly, while Filesystem::GetAssetData() converts / to \ (src/Filesystem/Module.cpp:67, src/Filesystem/Module.cpp:119). A sprite whose path uses / is not drawn on Windows. Use \\ in stored paths, or std::filesystem::path(p).make_preferred().
Files with the same name and different extensions share one asset path; only the first is registered. Give files unique names.
An asset is cached for the first type it is loaded as; loading it as another type returns a wrongly cast object (include/Filesystem/Importers/Importer.hpp:67). Load each file as one type.
TryLoadFile throws nullptr instead of returning an empty pointer (include/Filesystem/Importers/Importer.hpp:109). Check AssetExists or Filesystem::IsValid() first.
Filesystem::GetAssetData(const TObjectPtr<SAsset>&) looks the asset up by name, not path (src/Filesystem/Module.cpp:78). Use asset->GetAssetData().
Constructing an STypedSoftAssetPath from an SAssetData of another type runs throw; and terminates (include/Filesystem/FilesystemTypes.hpp:153). Construct it from a path string.
SConfig::Read() and SConfig::Save() don't compile if used; Get() re-reads the file on every call because bIsLoaded is never set (include/Filesystem/Config.hpp:20). Use Get() only, and cache the result.
Filesystem::Module() and Filesystem::Importers::Load (LDtk) are declared but not defined. Don't call them.

Rendering

Issue Workaround
Without any light, the screen is black: the lit image is only drawn when a light exists (src/Rendering/Vulkan_Renderer.cpp:625). Always have a light (a large-radius one lights everything).
Every texture batch on the Background layer clears the screen (the "cleared" flag is captured by value, src/Rendering/Vulkan_Renderer.cpp:730), so only the last Background texture is visible. If the Background layer is empty, nothing clears the screen and moving sprites smear. Use exactly one texture on the Background layer, covering the view.
Only the Entities layer is emptied each frame (src/Rendering/Vulkan_Renderer.cpp:783). Destroyed entities, or entities moved to another layer, stay drawn on the other layers. Put dynamic sprites on Entities; call Renderer::CleanupEntity() before destroying something on another layer.
If the first sprite of a batch has an invalid texture path, the whole batch is skipped (src/Rendering/Vulkan_Renderer.cpp:233). Make sure texture paths are valid.
Sprites with different textures on one layer are not depth-sorted against each other. Use a sprite sheet so sprites that must overlap correctly share a texture.
The window and render target are fixed at 1920 × 1080 (src/Rendering/Vulkan_Renderer.cpp:58); resizing stretches the image and breaks Renderer::ScreenPosToWorldPos(). Don't resize the window.
The flecs reflection registered for Graphics::SSprite lists members the struct doesn't have (src/Rendering/Module.cpp:55); flecs reports a size mismatch at shutdown. Editing or saving sprites in the Entity Debugger may be wrong. None needed for drawing.
Light Radius is in screen space, Falloff is ignored, the ambient level is fixed at 0.3, and the light count passed to the shader is a byte count (src/Rendering/Vulkan_Renderer.cpp:680). Tune Radius and Intensity by eye.
Renderer::AddDebugCollision() (deprecated) reads its rectangle as (x, y, height, width) (include/Rendering/Module.hpp:81). Renderer::LoadLevel() adds its collision rectangles starting at ID 0, which can clash with your IDs (src/Rendering/Module.cpp:93). Write to Renderer::CollisionInstances yourself, with IDs that can't clash.
Renderer::CleanupEntity() has no return statement when it succeeds (src/Rendering/RenderingBackend.cpp:62). Ignore its return value.

Input

Issue Workaround
Only the keyboard is read; gamepad buttons in bindings are ignored (src/Input/Module.cpp:100). —
Press bindings fire on keyboard auto-repeat (src/Input/Module.cpp:46). Track the key's previous state if you need one trigger per press.
Multi-key press and release bindings never trigger (src/Input/Module.cpp:65). Use hold bindings for combinations.
Each callback on an action runs once per callback registered on that action (include/Input/Module.hpp:96). Register at most one callback per action.
MULTIPLY and DIVIDE actions always give zero: values start from zero (include/Input/Module.hpp:71). Use ADD or OVERRIDE.
Keys typed into ImGui text fields also trigger game actions (src/Input/Module.cpp:44). Check ImGui::GetIO().WantCaptureKeyboard in your systems if it matters.

Editor and ImGui

Issue Workaround
The Dear ImGui demo window is always shown (src/Editor/Module.cpp:44). Collapse it; ImGui::SetWindowCollapsed("Dear ImGui Demo", true, ImGuiCond_Once) in a tool does it from code.
Component panels in the Entity Debugger can't be collapsed (a misplaced parenthesis in include/Gameplay/ECS/Components.hpp:43). —
Save Entity writes to Resources/Output/ECS/, which must already exist (src/Editor/EntityEditorTool.cpp:182). Create the folder.
ImGuiWrapper::TeardownModule() is never called. None needed.

Gameplay

Issue Workaround
The engine never calls GameplayFramework::Module(). Call it after Engine::InitializePlugins().
FMouseState::HoveredEntityId keeps the last hovered entity when the cursor leaves it (src/Gameplay/Module.cpp:62). Check MousePosition against the entity's box, as Collision and mouse hover does.
If FMouseState is missing from the global entity, the hover system dereferences a null pointer (src/Gameplay/Module.cpp:32). Only start it with GameplayFramework::ActivateMouseStateSystem().

Memory

Issue Workaround
Copy- and move-assigning a TObjectPtr that already holds an object doesn't release that object (include/Memory/Janitors.hpp:95). Clear() before assigning, if it may hold something.
TObjectPtr::operator* doesn't compile if used (include/Memory/Janitors.hpp:120). Use -> or Raw().
CastTo on an empty pointer crashes (include/Memory/Janitors.hpp:129). Check IsValid() first.

Logging

Issue Workaround
Trace (Verbose) messages are always dropped: Log::Module() sets spdlog's global level to debug (src/Log/Module.cpp:53). —
Timestamped copies of log files are named with the UTC time (src/Log/Module.cpp:62). —
Logger settings are read from statics whose initialization order across files is undefined. See Log. —
