Engine modules

The engine is one library made of ten modules plus a small core. Each module has its own folder, namespace and page.

Each module page starts with How to use, then explains the details and pitfalls, then lists the module's classes and functions. Folders are relative to include/ (headers) and src/ (sources).

Module What it does Folder Started by the engine Page
Engine core Starts the modules, runs the game loop, shuts down Module.hpp — Engine core
Log Named loggers built on spdlog Log/ 1st Log
Filesystem Registry of every file under Resources/, typed loading, custom asset types Filesystem/ 2nd Filesystem
ImGuiWrapper The shared Dear ImGui context and debug-panel registry Editor/ImGuiWrapper/ 3rd ImGuiWrapper
ECS The flecs world, component macros, built-in components, phases Gameplay/ECS/ 4th ECS
Renderer Sprites, layers, camera, lights, debug colliders, levels Rendering/ 5th Renderer
CoreEditor Editor tools: Entity Debugger, FPS Counter, your own tools and game UI Editor/ 6th CoreEditor
Memory TObjectPtr<T>, the reference-counted pointer Memory/ not needed Memory
CoreTypes Textures, sprites, LDtk levels, frame timing Types/ not needed CoreTypes
Input Actions with press, hold and release bindings Input/ not needed (updated every frame by the loop) Input
GameplayFramework Colliders, mouse hover, the Move2D action Gameplay/ no: call GameplayFramework::Module() yourself GameplayFramework

Which module do I need?

I want to… Read
Start the engine and run my game Engine core, Your first game
Create game objects and give them behaviour ECS
Draw sprites, move the camera, add lights Renderer
React to the keyboard Input
Load images, text or my own file types Filesystem
Show a score, a menu or a debug window CoreEditor
Detect overlaps or what the mouse is over GameplayFramework
Load a level made in LDtk CoreTypes, Renderer
Print messages to the console and log files Log
Share objects safely between systems Memory

How the engine is organized shows the start-up order and how the modules depend on each other.
