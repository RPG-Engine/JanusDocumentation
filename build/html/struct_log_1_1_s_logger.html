#include <Log/LogTypes.hpp>

Overview

Its outputs and minimum level come from its Log::SLoggerConfiguration. Declared in include/Log/LogTypes.hpp:43. Part of the Log module.

How to use

You rarely construct an SLogger yourself. DECLARE_LOGGER creates one for you, together with the Log::<Name>::Info(...) family of functions that log through it:

  1. In a source file, write DECLARE_LOGGER(MyModule, debug). This defines a static SLogger named LogMyModule inside namespace Log::MyModule.
  2. Call Log::MyModule::Info("Loaded {} items", count), or Error, Warning, Debug and Verbose.

Construct an SLogger directly only when you need a logger that is not tied to a namespace. Then pass it to the Log::Generic functions yourself, e.g. Log::Generic::Info(myLogger, "...").

Lifecycle

  1. Construction copies the configuration and calls Log::RegisterLogger() (src/Log/LogTypes.cpp:10).
  2. Registration creates an spdlog logger named Config.LoggerNamespace. It gets a file sink if LogOptions includes LOG_FILE and a colored console sink if it includes LOG_CONSOLE. If a logger with that name already exists, it is reused instead (src/Log/Module.cpp:78).
  3. Logging looks the spdlog logger up by name on every call and writes the message only if its level is at least Config.LogLevel (src/Log/Log.cpp:19).
  4. Shutdown: Log::TeardownModule() drops all spdlog loggers. The SLogger objects themselves stay alive until the program exits.

void RegisterLogger(const SLogger* Logger) {
const SLoggerConfiguration& config = Logger->Config;
if (std::shared_ptr<spdlog::logger> existingLogger =
spdlog::get(Logger->Config.LoggerNamespace);
existingLogger != nullptr) {
spdlog::trace(std::format(
"Logger {} found - Using existing logger instead of redefining...",
config.LoggerNamespace));
return;
}
spdlog::logger logger(config.LoggerNamespace);
if (HasAnyOptions(config.LogOptions, ELogOutputOptions::LOG_FILE)) {
logger.sinks().push_back(_Internal::GetSinkForFile(config));
}
if (HasAnyOptions(config.LogOptions, ELogOutputOptions::LOG_CONSOLE)) {
logger.sinks().push_back(std::move(
CreateSink<LogSinks::stdout_color_sink_mt>(_Internal::DefaultLogPattern,
config.LogLevel)));
}
logger.info("Logger initialized");
spdlog::register_logger(std::make_shared<spdlog::logger>(logger));
}

Notes

  • SLogger has no destructor of its own and no way to unregister. Treat loggers as objects that live for the whole program, the way DECLARE_LOGGER uses them.
  • If a message's logger name was never registered, or was dropped by Log::TeardownModule(), the message is replaced by an spdlog error Could not find logger <name>! (src/Log/Log.cpp:26).

Member Data Documentation

◆ Config

SLoggerConfiguration Log::SLogger::Config

Every log call reads Config.LoggerNamespace to find the spdlog logger and Config.LogLevel to decide whether to write the message (src/Log/Log.cpp:19). Raising LogLevel after construction filters out more messages from the next call. Lowering it, or changing anything else, has no effect, because the sinks keep the settings they were created with at registration.
