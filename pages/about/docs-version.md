# Documentation version {#docs_version}

<p class="lede">Which engine commit these pages describe, and how to bring them up to date from the engine's changes instead of re-reading the whole engine.</p>

| | |
| --- | --- |
| **Engine commit documented** | \docscommit |
| **Documented on** | \docsdate |
| **Examples verified** | Compiled with MSVC 14.51 (C++26, Release) and run against the same commit, with the one-line fix described in \ref known_issues |

Every GitHub link marked ↗ points at this commit, so line numbers always match the code they describe, even after the engine moves on.

## Where the version lives

`Documentation/docs-version.json` is the single source of truth:

| Field | Used for |
| --- | --- |
| `engineCommit` | The commit every source link points at. Shown in the top bar and the footer. |
| `documentedOn` | The date shown above. |
| `engineRepository` | Base URL for source links. |
| `examplesRef` | The branch whose `Documentation/examples` folder the example links point at (default `main`). |
| `examplesVerified` | Which commit the examples were last compiled and run against. |
| `coverage` | Which page documents which engine files. The delta tool uses it to tell you which pages a change affects. |

`build.ps1` reads this file and passes the values to Doxygen as environment variables, which the `Doxyfile` uses in its link aliases. Nothing else in the docs contains a commit hash.

## Updating the docs after engine changes

Run these from `Engine/Documentation` in PowerShell.

**1. See what changed** since the documented commit:

```
.\tools\docs-delta.ps1
```

It prints the commits since then, every changed engine file, the pages that document those files (from `coverage`), and every source link that points into a changed file, since their line numbers may have moved. Add `-WorkingTree` to include uncommitted changes, or `-Ref <commit>` to compare with a specific commit.

**2. Update the pages it lists.** For each changed file, read the diff (`git diff <documented commit> HEAD -- <file>`) and update the text, the tables and any `\engex` snippets. If a public API changed, update the examples that use it and rebuild them (\ref getting_started_examples).

**3. Check every source link** against the new code:

```
.\tools\docs-delta.ps1 -CheckLinks -Ref HEAD
```

It verifies that every `\src`, `\srclink`, `\srcdir` and `\engex` target exists, that line numbers are in range, and that the first line of every engine example still matches the source line it cites. Fix what it reports and run it again until it reports no problems.

**4. Move the pin and rebuild:**

```
.\tools\docs-delta.ps1 -Pin
.\build.ps1
```

`-Pin` sets `engineCommit` to `HEAD` (or `-Ref`) and `documentedOn` to today. Also update `examplesVerified` if you rebuilt and ran the examples.

**New engine files** that no `coverage` entry matches are reported as such: decide which page covers them and add an entry.

## Building these docs

The site is generated by [Doxygen](https://www.doxygen.nl) 1.18 with [Graphviz](https://graphviz.org) from `Engine/Documentation`:

```
powershell -File Engine\Documentation\build.ps1
```

Then open `Engine/Documentation/build/html/index.html`. The build aims for zero warnings; they are written to `build/warnings.log`.

| Folder or file | Contains |
| --- | --- |
| `pages/` | Guides (`.md`), module pages (`api/*.dox`), example pages (`examples/`), this section (`about/`) |
| `examples/` | The example programs and their `CMakeLists.txt`. Code shown on the pages comes from these files (`\snippet` and `\include`), so the docs always show compiled code. |
| `images/` | Screenshots of the examples |
| `doxygen/` | The site theme: header, footer, stylesheet, sidebar (`janus-nav.js`) and page script |
| `tools/docs-delta.ps1` | The update and link-check tool |
| `docs-version.json`, `Doxyfile`, `build.ps1` | Version, Doxygen settings, build script |

When you add a page or a documented class, also add it to the sidebar in `doxygen/janus-nav.js`.

See \ref conventions for the markers and aliases used in the pages.
